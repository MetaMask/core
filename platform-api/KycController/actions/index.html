KycController:startSumSub​

Source: packages/kyc-controller/src/KycController-method-action-types.ts:202

Runs the SumSub document-verification sub-flow end to end:

  1. creates a UKYC session, receiving per-secret encryption schemas;
  2. verifies the encryptionDataKey schema's jwtChain against the idOS enclave JWKS and the ukycCapabilityToken schema's jwtChain against the idOS relay JWKS, then confirms each attested session server public key;
  3. derives the data_encryption_key from the wallet's UKYC local_user_secret and wraps it for the session server;
  4. mints a client-signed, read-only ukyc_capability_token, wraps it the same way as the encryption key, and submits both via authorizations;
  5. fetches the SumSub applicant access token; and
  6. presents the SDK via the injected launcher.

If a UKYC session already exists (the consents path creates it before recording session disclaimers), steps 1–4 are skipped.

If authorizations report the applicant is already approved on the relay while the vendor is still finalizing (kycStatus: approved, finalStatus: pending), the sub-flow stops at step 4 with a vendorProcessing status and a message rather than launching the SDK.

Parameters:

NameDescription
paramsOptional parameters.
params.localeBCP-47 locale for the SDK UI.
params.debugEnables SDK debug logging.

Returns: The SDK result.

Handler signature:

(params?: {
    locale?: string;
    debug?: boolean;
  }) => Promise<Record<string, unknown>>
